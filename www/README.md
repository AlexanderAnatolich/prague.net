# Prague website & docs

Static site for Prague, built from two pieces and glued together at deploy time:

| Path | Stack | Output |
| --- | --- | --- |
| `www/site/` | Vite + React 19 + Tailwind v4, **prerendered to static HTML** (no JavaScript is shipped) | `www/site/dist/` |
| `www/docs/` | DocFX (modern template + brand layout/CSS override) | `www/docs/_site/` |

Deployed to GitHub Pages by `.github/workflows/pages.yml` on every push to `main` that touches
`www/**`, `src/**` (the API reference is compiled from the source), `docs/llm-readme.txt` or
`Directory.Build.props`, and whenever a GitHub release is published. It can also be run by hand
(`workflow_dispatch`).

Live at **https://nanov.github.io/prague.net/** — landing at the root, docs at `/docs/`, API reference
at `/docs/api/`. The Vite app sets its `base` to `/prague.net/` at build time so asset paths resolve
under the project-page subpath.

## What the site serves for machines

| Path | Purpose |
| --- | --- |
| `/robots.txt` | Allows everything, points at both sitemaps. |
| `/sitemap.xml`, `/docs/sitemap.xml` | Landing page, and every docs/API page (generated by DocFX). |
| `/llms.txt` | Short index for LLM crawlers in the llms.txt convention: summary + links to every doc page. |
| `/llms-full.txt` | Copy of `docs/llm-readme.txt`, the dense source-checked reference for coding assistants. |
| `/404.html` | GitHub Pages serves it for unknown paths. |

The landing page is plain HTML: the React tree is rendered at build time (`scripts/prerender.mjs`) and
no script tag is emitted, so crawlers, screen readers and browsers with scripts disabled all get the
full content. Open Graph / Twitter metadata and a `SoftwareSourceCode` JSON-LD block are in
`www/site/index.html`. Docs pages get their `<meta name="description">` from the `description:` front
matter of each article.

## Build locally

```bash
# Landing
cd www/site
npm install
npm run dev       # http://localhost:5173  (dev server, live React)
npm run build     # dist/ — static HTML + one stylesheet

# Docs (requires .NET 9 and .NET 10 SDKs, because the projects multi-target both)
dotnet tool install -g docfx     # one-time
cd www/docs
docfx docfx.json --serve         # http://localhost:8080
```

## Build everything (mirrors the CI pipeline)

```bash
(cd www/site && npm ci && npm run build)
(cd www/docs && docfx docfx.json --metadata _pragueVersion=$(gh release view --json tagName --jq '.tagName | ltrimstr("v")'))
rm -rf www/_dist && mkdir -p www/_dist/docs
cp -R www/site/dist/. www/_dist/
cp -R www/docs/_site/. www/_dist/docs/
cp docs/llm-readme.txt www/_dist/llms-full.txt
```

Preview under the real subpath (links are absolute to `/prague.net/`):

```bash
mkdir -p /tmp/prague-www && ln -sfn "$PWD/www/_dist" /tmp/prague-www/prague.net
(cd /tmp/prague-www && python3 -m http.server 8123)   # http://localhost:8123/prague.net/
```

## Deploy

1. One-time: **Settings → Pages → Source** must be **"GitHub Actions"**.
2. Push to `main` (or **Actions → Build and deploy Prague website → Run workflow**).

The version pill in the docs sidebar is the newest stable GitHub release (the same source
`release.yml` bumps from; `<Version>` in `Directory.Build.props` is only a bootstrap fallback). CI passes
it to DocFX as `--metadata _pragueVersion=…`; without that flag the pill is not rendered, so a local
`docfx --serve` shows no version rather than a stale one. Publishing a release also triggers a site
deploy, so the pill updates on its own.

## Brand assets

Logo PNGs live in `www/site/public/` (`logo-mark.png`, `logo-full.png`); the alternates the designer
produced are kept in `www/site/src/assets/images/` and are not shipped. The DocFX brand override
(`www/docs/templates/prague/public/main.css`) re-uses the same color tokens (`--brand-orange #F27D26`,
`--brand-black #141414`) and fonts so the two halves of the site feel like one.

## Adding a doc article

1. Create the Markdown file in `www/docs/articles/` with `title:` and `description:` front matter and a
   single `# H1` (the layout does not add its own title).
2. Add an entry to `www/docs/toc.yml` and a line to `www/site/public/llms.txt`.
3. Rebuild (`docfx docfx.json --serve`).

## Editing the landing

Edit `www/site/src/App.tsx`. It is rendered once at build time with `renderToStaticMarkup`, so it must
stay free of hooks, effects and event handlers; use CSS for motion (and respect
`prefers-reduced-motion`). `import.meta.env.BASE_URL` resolves to `/` in dev and `/prague.net/` in
production builds — use it for any cross-page link (e.g. `${BASE_URL}docs/`).

## Code samples are compiled

Every C# block on a docs page is pulled out of `samples/Prague.Samples/`, an NUnit project that
`dotnet test Prague.Tests.slnf` builds and runs in CI, so an example cannot stop compiling or stop
being true without a test going red. The articles contain no hand-written C#.

- `samples/Prague.Samples/Models/` is the one domain every page uses (`Order`, `Customer`, `OrderLine`,
  `Shipment`, `Product`, `CustomerActivityIndex`). Add attributes to these models rather than inventing
  new entities; each file opens with a `// docs:` line saying what it demonstrates.
- One folder per docs section (`GettingStarted/`, …), one test class per article. Each block is a
  `#region kebab-name` … `#endregion` containing exactly the code the reader should see; assertions and
  set-up stay outside the region. Region names are unique within a file and describe the block, not
  the test (`write-and-query`, `direct-index-access`).
- A page references a region with DocFX's code-snippet syntax, relative to the article:

  ```markdown
  [!code-csharp[](../../../../samples/Prague.Samples/GettingStarted/QuickStart.cs#write-and-query)]
  ```

  DocFX reads the file from disk at build time (paths outside `www/docs` are fine), strips the
  `#region` lines and renders the body with the common indentation removed. Rename the region and the
  build warns `codesnippet-not-found`, so run `docfx build docfx.json` after moving one.
- Run the samples alone with `dotnet test samples/Prague.Samples`. Every test must pass on both target
  frameworks before the page that cites it is merged.
